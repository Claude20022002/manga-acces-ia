## Décision : Qwen3-VL-4B-Instruct reporté hors Phase 2

CLAUDE.md décidait "Qwen3-VL-4B-Instruct, Q4 quantisé" pour la description de
scène. Recherche sur la model card officielle
([Qwen/Qwen3-VL-4B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct))
et sur le GGUF officiel
([Qwen/Qwen3-VL-4B-Instruct-GGUF](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct-GGUF)) :

- Chemin quantisé Q4_K_M (2.5 Go) : support de l'architecture Qwen3-VL dans
  llama.cpp/llama-cpp-python non stabilisé côté officiel (issue ouverte
  [ggml-org/llama.cpp#16207](https://github.com/ggml-org/llama.cpp/issues/16207)),
  nécessite un fork communautaire non-officiel.
- Chemin officiel `transformers` BF16 : ~8 Go de poids seuls sur une machine
  à 10 Go RAM réellement disponibles → OOM quasi-certain en pipeline
  séquentiel.

**Verdict** : ni l'un ni l'autre n'est acceptable pour un projet visant la
reproductibilité à $0. Qwen3-VL est reporté à une phase ultérieure, quand le
support llama.cpp sera stable et officiel. Pas d'alternative à la stack
proposée sans raison — c'est un report, pas un changement de stack.

## Tâche 2 : script narratif — fait

Schéma `NarrativeScript`/`NarrativeSegment` (`schemas/narrative_script.py`)
et assemblage `build_narrative_script()` (`pipeline/narrative_builder.py`) :
transforme un `MangaPage` en liste ordonnée de segments (voix + texte), un
segment par description de scène ou élément de texte, prêt pour un futur
appel `TTSBackend.synthesize()`. Règles : voix personnage si `speaker_id`
résolu sinon `voice_unknown`, narration/description en `narrator`, SFX
formatés entre crochets (`"[ドン]"`). TODO explicite dans le code : l'ordre
des éléments par panel suit l'ordre de détection Magiv2, pas un tri spatial
(candidat Phase 3). 8 tests dédiés.
