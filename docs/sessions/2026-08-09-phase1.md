# Session 2026-08-09 — Phase 1 : pipeline Magiv2 → OCR → MangaPage

## Jalon atteint

Pipeline end-to-end fonctionnel, de bout en bout, sur CPU :

```
load Magiv2 → detect() → unload Magiv2 → load manga-ocr → recognize() par bbox → unload manga-ocr → assemble MangaPage
```

Implémenté dans `StructureBackend`/`OCRBackend` (`backends/base.py`, `load()`/`unload()`
contractualisés dans l'interface), `Magiv2Backend` (`backends/magiv2_backend.py`),
`MangaOCRBackend` (`backends/manga_ocr_backend.py`) et `PageProcessor`
(`pipeline/page_processor.py`, injection de dépendance des deux backends).

Exécuté avec succès (`exit code 0`) sur `data/manga/test_kitazawa_1902.jpg`,
produisant un **`MangaPage` JSON valide** conforme au schéma v1.

## Contrainte `transformers<5.0` — cause exacte

`transformers>=4.45.0,<5.0` (borne basse alignée sur la contrainte réelle de
`manga-ocr` : `transformers>=4.45.0` sans plafond côté manga-ocr, vérifié via
`uv pip show manga-ocr` — pas de conflit de résolution).

`transformers` 5.x (résolu par défaut en 5.14.1 vu l'absence de plafond initial) a
réécrit l'architecture de tokenizer (`TokenizersBackend`) et casse la conversion
automatique lent→rapide du tokenizer TrOCR interne à Magiv2 (RoBERTa/BPE, `vocab.json` +
`merges.txt`, pas de `tokenizer.json`). Le message d'erreur (`sentencepiece or tiktoken`)
est un fallback générique de `transformers`, pas la vraie cause — confirmé en lisant le
code source de `tokenization_utils_tokenizers.py` : la conversion BPE échoue avant même
d'atteindre la branche sentencepiece/tiktoken. `sentencepiece` a été ajouté sur un premier
diagnostic incomplet ; la vraie cause était la version de `transformers`.

Testé et validé avec `transformers==4.57.6`.

## Observation — image Kitazawa 1902

- **6 panels détectés**, ordre de lecture cohérent (droite→gauche, haut→bas).
- **5 clusters de personnages** détectés, sans nom associé (attendu — Magiv2 seul ne
  nomme pas, cf. `Character.name = None` en Phase 1).
- **1 seul élément de texte reconnu** sur toute la planche (`"ならねえからお」"`,
  panel-2). Les 5 autres panels n'ont aucun texte associé — soit Magiv2 n'a détecté
  qu'une bbox de texte au total, soit d'autres bboxes détectées avaient leur centre hors
  de tout panel et ont été silencieusement ignorées (comportement accepté en Phase 1).
  Cohérent avec l'observation de la baseline Phase 0 : ce strip de 1902 est **hors
  distribution d'entraînement** des modèles (manga-ocr et probablement Magiv2, entraînés
  sur du manga imprimé moderne) — pas une preuve de bug, pas non plus une preuve de
  qualité du pipeline.
