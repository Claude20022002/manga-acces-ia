# Session 2026-08-09 — Phase 3, lancement

## Jalon : premier fichier audio produit

Pipeline complet exécuté bout en bout sur `data/manga_jpg/3-1.jpg` :
Magiv2 → manga-ocr → `describe_panel()` → `build_narrative_script()` →
`assemble_audio()` avec `KokoroBackend`. Résultat : `data/outputs/3-1.opus`,
5 segments (3 descriptions de scène + 2 dialogues), 25.29s, opus 48kHz mono
valide (`ffprobe` confirmé).

## KokoroBackend

`backends/kokoro_backend.py` — implémente `TTSBackend`, même forme
load/unload que `Magiv2Backend`/`MangaOCRBackend`. Poids int8 (88 Mo,
`models/kokoro/kokoro-v1.0.int8.onnx` + `voices-v1.0.bin`, 27 Mo),
téléchargement manuel depuis les releases GitHub de kokoro-onnx (pas de
fetch automatique HuggingFace comme pour Magiv2/manga-ocr). Chargement
mesuré : 0.73s. `synthesize(text, voice_id, lang="en-us")` retourne des
bytes WAV (via `soundfile`), pas du PCM brut — permet à pydub de charger
chaque segment sans connaître le sample rate hors bande.

Dépendance système cachée découverte : `espeak-ng` (phonémisation
kokoro-onnx), déjà présente sur cette machine, documentée dans le README.

`TTSBackend.synthesize()` modifié dans `backends/base.py` pour ajouter le
paramètre `lang` (défaut `"en-us"`), en prévision du passage à `"ja"` une
fois la traduction Qwen3-VL intégrée.

## AudioAssembler

`pipeline/audio_assembler.py` — `assemble_audio(script, tts_backend,
output_path)` : charge le backend, synthétise chaque segment du
`NarrativeScript` dans l'ordre, insère 300ms de silence entre segments
consécutifs (pas de silence final), concatène et exporte en `.opus` via
FFmpeg (pydub), décharge le backend, log durée totale + nombre de segments.

Deux blocages d'environnement résolus avant l'implémentation :
- `pydub` cassé sous Python 3.14 (`audioop` retiré de la stdlib en 3.13+,
  repli sur `pyaudioop` absent) — corrigé par `audioop-lts>=0.2.2;
  python_version >= '3.13'` dans `pyproject.toml`.
- Binaire `ffmpeg` absent du système (seules les bibliothèques étaient
  présentes via dépendances transitives) — installé manuellement
  (`sudo apt install ffmpeg`).

## Tests

`tests/test_audio_assembler.py` — 5 tests avec `TTSBackend` factice
(WAV silencieux généré via le module stdlib `wave`, pas de vrai Kokoro) :
script vide, segment unique, segments multiples (durée = somme + silences),
création automatique du dossier de sortie, `load()`/`unload()` appelés
exactement une fois. **33/33 tests passent** (28 existants + 5 nouveaux).

## Limitation connue : prononciation

Le premier audio produit est mal prononcé : texte japonais brut
(`text_original` OCR, non traduit — Qwen3-VL reporté, cf. session Phase 2)
lu par des voix anglo-américaines (`af_sky`/`af_bella`). Limitation
documentée et acceptée pour ce jalon walking-skeleton — l'objectif était de
valider la mécanique texte → audio bout en bout, pas la justesse
linguistique.
